## 2. 产品概述

### 2.1 背景与机会

1. **语言启蒙窗口期**：3–8 岁是语音习得与语感建立的黄金期。三语并行（母语中文锚点 + 英语过渡 + 法语目标）在科学排期下互不干扰，且三语对照能让孩子在比较中建立「语言通用感」。
2. **幼儿园适应痛点**：入园分离焦虑、听不懂老师指令、不敢表达需求（如厕/喝水/求助）、同伴冲突处理，是 3–6 岁家庭最高频的焦虑点。用「场景句 + 角色对话 + 情绪卡」提前演练，可直接降低适应成本。
3. **幼小衔接与中法双体系需求**：目标用户中相当一部分面临「国内幼升小」或「在法/赴法入学（CP 起步）」双轨选择。家长需要一套**既符合中国数学教学进度、又对齐法国 CP/CE1/CE2** 的启蒙内容——中国低年级数学进度显著快于欧美（详见 6.8 节难度差异），直接采用欧美数学内容会「吃不饱」。
4. **现有产品的扩展空间**：v1 已验证「三语对照 + TTS + 测验 + 激励」闭环可用，但内容只有句子/故事，学科单一、无分龄、体验静态（无动画/音乐/拼写），具备明确的结构化升级路径（manifest 已为 songs/dialogues 占位、跟读链路待修复）。

### 2.2 产品定位（一句话）

> **面向 3–8 岁孩子的中英法三语全学科启蒙平台**：以「听—说—玩—唱—拼—算—想」多感官方式学语言、练数学、玩逻辑、适应幼儿园，全程中英法三语对照，家长一键分龄。

### 2.3 目标用户与画像

**主用户：3–8 岁儿童（按学段细分，是第 6 章分龄体系的输入）**

| 学段 | 年龄 | 中国学制 | 法国学制 | 发展特征（设计约束） |
|------|------|---------|---------|---------------------|
| L1 | 3–4 岁 | 幼儿园小班 | Petite section（PS） | 注意力 5–10 分钟；具象思维；喜欢重复；精细动作发展中，**仅可点按、不宜拖拽**；不识字，**纯音频驱动** |
| L2 | 4–5 岁 | 幼儿园中班 | Moyenne section（MS） | 注意力 10–15 分钟；可完成简单拖拽；能理解「轮流/规则」；开始对符号感兴趣 |
| L3 | 5–6 岁 | 幼儿园大班 | Grande section（GS） | 注意力 15–20 分钟；可独立完成 3–5 步操作；对字母/数字敏感；能进行简单自我评价 |
| L4 | 6–7 岁 | 幼小衔接 / 一年级 | CP（Cours préparatoire） | 注意力 20–25 分钟；可独立学习 10–15 分钟单元；进入系统识字与计算启蒙 |
| L5 | 7–8 岁 | 一年级 / 二年级 | CE1（Cours élémentaire 1re année） | 可独立完成任务链；乘法口诀/竖式学习期；喜欢「闯关/收集/对战」类玩法 |
| L6 | 8 岁+ | 二年级 / 三年级上 | CE2（Cours élémentaire 2e année） | 自主学习为主；本期仅规划内容框架（见 6.7），详细题型在 v2.2+ 展开 |

**辅助用户：家长**

- 画像：25–40 岁，关注语言启蒙与幼小衔接；部分家庭有法国生活/移民/国际学校背景，需要「中法两套体系都能对上」的内容。
- 诉求：一键选学段（不懂教育理论也能配对正确难度）、看得到学习成果（周报）、控制使用时长、内容安全可信（无广告无外链）。

**内部用户：内容维护者**

- 诉求：继续用 `data/*.md` 低成本扩充内容；v2 新增 6 类内容文件均有**固定格式规范**（第 9 章），无需改代码。

### 2.4 典型使用场景（用户故事 · Scenario）

**场景 A｜早晨 15 分钟 · 分龄每日闭环（L2 中班，4 岁）**
妈妈打开网站 → 首页吉祥物小狐狸 Félix 用法语说 "Bonjour !" → 点击「今日挑战」→ 完成 3 道语言题（听音选图）+ 2 道数学题（点数 1–10）+ 1 道逻辑题（AB 颜色规律）→ 每答对一题 Félix 跳起撒花 → 结束后喂 Félix 一颗苹果，打卡 +10 分。全程孩子不需要识字，按钮均为「图标 + 语音」驱动。

**场景 B｜入园前演练 · 幼儿园适应（L1 小班，3 岁）**
九月入园前一周，妈妈进入「我的幼儿园一天」场景路径，和孩子一起看「和妈妈说再见」对话：老师角色句自动播放（"Au revoir maman !"），轮到孩子角色时点击跟读（"妈妈下午来接我"三语对照）。孩子入园第一天，用学过的句子向老师问好。

**场景 C｜数学闯关 · 中国进度不降速（L5，7 岁）**
一年级孩子完成学校作业后，打开「数学闯关」→ 选择「表内乘法 · 6 的口诀」关卡 → 60 秒限时口算 10 题，答对 9 题得两颗星 → 星星计入激励体系，错的 1 题进入错题本，明天的「今日挑战」自动复习。家长中心周报显示：本周数学口算正确率 88%，建议巩固「7×8」。

## 3. 产品目标与成功指标

### 3.1 产品目标（v2.0 交付时）

1. **分龄可用**：3–8 岁每个学段都有匹配其认知水平的内容、题型与评分标准，家长可一键切换。
2. **学科齐备**：语言（听说读拼）+ 数学（对齐中国体系，标出法国对标）+ 逻辑（中法融合）三大学科均有关卡化学习路径。
3. **多感官体验**：所有内容可听（TTS）、可跟读（评分）、可看（动画反馈）、可唱（儿歌卡拉OK）、可拼（拼写游戏）。
4. **闭环完整**：学习 → 测验 → 错题 → 复习 → 激励 → 周报，数据全部本地化。
5. **内容可扩展**：6 类新增内容文件格式规范固化，内容维护者零代码扩充。
6. **儿童安全合规**：无广告、无外链、无数据采集，家长门隔离设置项。

### 3.2 北极星指标

> **每周完成「每日挑战 ≥ 5 天」的活跃学段数（Weekly Engaged Levels）**——同时衡量留存、分龄适配与每日闭环质量。

### 3.3 关键指标（KPI）

| 类别 | 指标 | 目标（上线 3 个月） |
|------|------|--------------------|
| 学习效果 | 每日挑战完成率 | ≥ 60% 的启动日完成整套挑战 |
| 学习效果 | 跟读打分通过率（≥ 学段及格线） | ≥ 70% |
| 学习效果 | 数学关卡首次三星率 | ≥ 50% |
| 参与 | 人均单次使用时长 | 落在家长设定上限的 70–100% 区间（说明不过度沉迷也不流失） |
| 参与 | 连续打卡 7 天用户占比 | ≥ 30% |
| 覆盖 | 三学科周覆盖率 | 每周同时使用 ≥ 2 个学科的用户 ≥ 50% |
| 内容 | 学段出口里程碑达成率 | 各学段核心里程碑达成 ≥ 50%（如 L4：20 以内加减正确率 ≥ 90%） |

## 4. 幼儿产品设计原则

本原则是所有功能设计（第 7 章）的**上位约束**，验收时逐条对照。

| # | 原则 | 设计要求 |
|---|------|---------|
| P-1 | **音频先行** | 所有可交互元素点击/聚焦后有语音反馈；核心任务不依赖识字；按钮 = 大图标 + 短文案 + 自动朗读 |
| P-2 | **大触控区** | 可点按元素 ≥ 48×48px（实际视觉 ≥ 64px），元素间距 ≥ 16px；拖拽目标吸附容差 ≥ 32px |
| P-3 | **单屏单任务** | 每屏只呈现一个任务/问题；无滚动嵌套；步骤不超过 3 步可见 |
| P-4 | **即时正向反馈** | 答对 ≤ 300ms 内动效+音效；答错不打叉不扣分，用「再试一次」引导（小班/中班题可无限重试） |
| P-5 | **重复无害** | 同一内容可无限次重听/重玩，无次数惩罚 |
| P-6 | **家长门（Gate）** | 一切设置、备份、内容开关、时长调整入口必须通过家长门（见 F45） |
| P-7 | **无广告无外链** | 站内不出现任何第三方广告、外链、UGC 输入框（除录音） |
| P-8 | **动效有度** | 动效服务于理解与激励，单屏同时运动元素 ≤ 2；尊重 `prefers-reduced-motion`（见 M3） |
| P-9 | **数据本地化** | 无账号、无埋点上报、无云端存储；学习数据仅 localStorage（隐私合规见第 11 章） |
| P-10 | **三语等权** | 所有学习内容三语同屏同权重呈现（中文锚点、英文过渡、法语目标），界面语言默认中文（界面多语言切换列为 P2 开放项） |

## 6. ★ 分龄学习体系与内容规划（专门章节）

> 本章是 v2.0 的**内容地基**：所有模块（M5–M10）的出题池、难度参数、评分线均从本章的学段定义派生。
> 配置落点：`lib/levels.ts` 定义 `Level`（L1–L6）与各学段参数（题型开关、及格线、限时、每题重试次数等），家长在学段选择器（F17）中选定后，全站内容池/难度随之切换。

### 6.0 体系设计说明

1. **语言：三语等权对照**。每个知识点（词、句、儿歌句、题干）均提供 `zh / en / fr` 三语。中文是理解锚点，英语是过渡桥，法语是目标语言（也可反向使用——法国家庭用本产品学中文）。
2. **数学：以中国教学体系为基准**。知识点排期遵循部编/人教版幼儿园数学启蒙与小学数学节奏，**不做「欧美同年级等难度」降级**——例如表内乘法按中国二年级（7–8 岁）完整掌握九九口诀，而不是照搬欧美 CE1 阶段只学 2/5/10 的口诀。每个数学知识点标注**法国对应学段**，方便在法孩子对照 CP/CE1/CE2 课程同步复习（详见 6.8）。
3. **逻辑推理：中法融合**。将中国思维训练题型与法国 maternelle/élémentaire 的 logique 教学传统（sériation、algorithme、jeux de déduction、labyrinthe、sudoku）归并为**六大能力域**统一出题（见 6.9 表），每个能力域注明题式中/法来源。
4. **幼儿园生活适应**：L1–L3 为主战场（场景路径 + 对话 + 情绪卡），L4 起自然过渡为「校园规则与自主管理」。
5. **难度递进原则**：同一题型跨学段复用（降低开发成本），通过**学段参数**改变难度（数量范围、选项数、限时、重试次数、及格线），而非开发独立题型。

### 6.7 L6 · 8 岁+（二年级 / 三年级上 / CE2）拓展期（本期仅框架）

- 学段定位：为 8 岁+ 用户预留内容与难度框架，**v2.0 交付学段选择器选项与占位内容**，详细题型与内容包在 v2.2+ 展开。
- 数学方向（中国体系）：万以内加减法；乘除法竖式；分数初步（几分之一）；周长；时间计算；统计表。
- 法国对标（CE2）：multiplication posée、division avec reste、fractions simples、périmètre。
- 逻辑方向：数独 9 宫入门；逻辑网格标准版；综合应用题（价格计算 + 折扣）。
- 语言方向：章节故事、日记写作、法语动词变位感知（être/avoir 直陈式现在时）。

### 6.8 数学难度差异说明（为什么以中国体系为基准）

| 知识点 | 中国体系节奏 | 法国节奏 | 差异与产品策略 |
|--------|-------------|---------|---------------|
| 数的认识 | 大班认 1–20，一年级上 100 以内 | CP 认 0–100 | 基本同步；中国更早强调数位/位值概念 → 中国节奏为主线 |
| 加减法 | 大班 10 以内 → L4 20 以内进退位 → L5 100 以内口算+竖式 | CP 20 以内 → CE1 进位与 100 以内 → CE2 竖式系统化 | **中国快约 0.5–1 年**；欧美/法国同年级内容对本产品用户「太简单」，故以中国排期为基准 |
| 乘法 | 二年级上（7–8 岁）九九口诀全表背诵 | CE1 仅引入 2/5/10（再 3/4），CE2 才完整 | **中国快约 1 年**；乘法关卡按九九口诀设计，法国对标仅作参考标注 |
| 除法 | 二年级下表内除法 | CE2 引入 | 快约 1 年 |
| 测量与货币 | 一年级人民币、二年级 cm/m 与克千克 | CE1 euros 与 cm/m | 大致同步，双币种认知均支持（人民币为主、欧元为拓展） |
| 应用题 | 一年级起大量文字应用题，题干语言复杂 | 更偏情境开放 | 应用题三语呈现，语言门槛由「三语对照」化解，语言+数学双重习得 |

**结论**：数学关卡一律按中国知识点排期出题与评星；法国对标以「同步学」标签呈现在关卡详情中（如「本关 ≈ CP 第 2 学期」），满足在法家庭对照校准需求。

| 能力域 | 中式题式来源 | 法式题式来源 | 代表玩法 |

**核心流程（跟读修复后链路）**：LiveQuizModal 打开 speak 题 → 渲染 SpeakQuizCard（接收 onRecognize）→ 点击 🎤 → SpeechRecognition（maxAlternatives=5）→ `scorePronunciation` → 回填 `speakResults[i]`（score/transcript/feedback + userIndex）→ 全部完成后提交结算。

**评分算法规格（评审 P1-4）**：`scorePronunciation` 为现有纯函数实现（`lib/pronunciation.ts`，完整规格见 v1 PRD §7），v2 复用不重写——

- **输入**：`target`（目标文本）、`candidates[]`（ASR 候选，最多 5，含 `transcript` / `confidence`）、`lang`（"fr" | "en"）。
- **输出**：`{ score: 0–100 整数, transcript, matched[], missing[], extra[], precision, recall, feedback[] }`。
- **管线**：normalizeText（小写 → NFD 去变音符 → 删撇号 → 非字母数字转空格）→ tokenize → pickBestCandidate（逐候选算词级 F1 取最高，并列取高置信度）→ alignWords（LCS 词级对齐 → matched/missing/extra）→ `score = round(100 × (0.7·F1 + 0.3·confidence))`（confidence 缺省 0.8）→ buildFeedback（分档文案 + 法语联诵/鼻化元音、英语 th/r 等语种 tips）。
- **复用规则**：单词跟读（2.5）与句子跟读共用同一管线（target 为单词时退化为单词 F1）；儿歌跟唱（2.6）同管线，仅及格线放宽 10 分。
- **学段及格线（BUG-4）的作用域**：只影响「通过判定 → `userIndex` 回填 → 积分/错题隔离」，**不改变 score 的计算方式与取值范围**；评分算法本身无学段差异。

**解析器行为规格（`lib/parser.ts` v2 契约，评审 P1-5）**

1. **两种三语写法**（同一文件内可混用）：
   - **多行组（推荐，v1 兼容）**：连续 `- zh: / - en: / - fr:` 三行构成一条内容，遇 `fr` 行触发 flush（v1 现行为）。
   - **单行紧凑写法**：`- <key>: <zh> | <en> | <fr>`，` | ` 分隔的**字段顺序固定为 zh → en → fr**（位置语义，不随书写者习惯变化）。
2. **角色行（dialogues 专用）**：`- <role> <lang>: <text>`（如 `- A zh: 老师早上好！`），按「role + lang」键名识别，**顺序无关**；同一 role 的三个语言行构成一个 turn。
3. **标量键附着规则**：`- level: / - category: / - scene: / - emoji: / - audio: / - kind: / - domain:` 等单值键附着到**当前 `##` 分组内、其后的第一条内容项**；分组内多条内容时，附着键只作用于紧随其后的一条。
4. **`##` 分组语义**：stories/songs 中为「标题」（→ `Story.title` / `Song.title`）；**sentences 中为「主题」→ 新增 `category` 字段**（v1 现忽略该标题，v2 捕获用于主题/场景过滤）；logic/math-bank 中为「题组名」。
5. **向后兼容**：现有 `sentences.md` / `stories.md` 零修改可解析——无 `level:` 归入 L3/L4 通用池，无 `scene:` 则场景过滤不命中。
6. **转换示例**（单行紧凑写法 → 解析结果）：

   ```markdown
   - stem: 谁偷吃了蛋糕？| Who ate the cake? | Qui a mangé le gâteau ?
   ↓ 解析为
   { stem: { zh: "谁偷吃了蛋糕？", en: "Who ate the cake?", fr: "Qui a mangé le gâteau ?" } }
   ```

7. **校验与单测**：缺任一语言字段、`level` 非法值、单行写法 ` | ` 数量不足 2 → 解析告警（P1 校验脚本拦截，CI 可选）；解析器测试用例必须覆盖：两种写法混排、角色行乱序、v1 文件回归。

### 9.5 数学生成器接口规格（`lib/mathGenerator.ts`，评审 P0-2）

```ts
type Rng = () => number;   // 可注入伪随机源（mulberry32）；种子 = 日期/关卡id，保证同种子同卷
type MathKind = "count" | "countWrite" | "compare" | "add" | "sub" | "addCarry" | "subBorrow"
              | "placeValue" | "sequence" | "clock" | "money" | "wordProblem" | "mul";

type MathQuestion = {
  id: string;                            // `${kind}_${seed}_${index}`；seed 为日期/关卡 id → 同种子同卷（不用时间戳，保证确定性）
  subject: "math"; level: Level; kind: MathKind;
  source: "generated" | "fixed";         // 生成器题 / math-bank.md 固定题（吸收补充稿 B）
  fixedId?: string;                      // source = "fixed" 时指向 math-bank.md 条目 id
  prompt: { zh: string; en: string; fr: string };
  answer: string;                        // 统一字符串（数字 / ">"|"<"|"=" / "h:mm"），判等前规范化；不用 string|number 混型，规避 "12" ≠ 12
  unit?: string;                         // 计量单位（"cm"、"元"…），仅展示用（吸收补充稿 B）
  image?: string;                        // 预留：emoji 或图片路径（与全站 image 字段策略一致）
  inputMode: "keypad" | "choice";        // 学段驱动：L1–L2 = choice，L3+ = keypad
  options?: string[];                    // inputMode = "choice" 时必填
  explanation?: { zh: string; en: string; fr: string };
  visual: CountVisual | CompareVisual | ArithVisual | PlaceValueVisual
        | SequenceVisual | ClockVisual | MoneyVisual | WordProblemVisual;  // 按 kind 判别
};

type CountVisual      = { emoji: string; count: number };                          // count / countWrite
type CompareVisual    = { left: { emoji: string; count: number };
                          right: { emoji: string; count: number } };               // answer: ">" | "<" | "="
type ArithVisual      = { a: number; b: number; op: "+" | "-";
                          decomposition?: { label: { zh: string; en: string; fr: string };
                                            text: string }[] };
                          // addCarry / subBorrow 必附 decomposition（凑十/破十步骤）
type PlaceValueVisual = { tens: number; ones: number; hundreds?: number };   // L5 三位数拓展
type SequenceVisual   = { items: (number | "?")[]; step: number };                 // answer = "?" 处的值
type ClockVisual      = { hour: number; minute: 0 | 15 | 30 | 45 };          // L3/L4 用 0/30；15/45 为 L5 可选刻钟
type MoneyVisual      = { mode: "count" | "pay"; currency: "CNY" | "EUR";
                          notes: number[]; price?: number };                 // 人民币为主、欧元为拓展（§6.8）
type WordProblemVisual= { emoji: string; a: number; b: number; op: "+" | "-" | "×" };

type MathGenerator = (params: { level: Level; kind: MathKind; rng: Rng }) => MathQuestion;
```

**各生成器硬约束（出题有效性，作为单测断言项）**

| kind | 约束（数值范围随学段） |
|------|----------------------|
| count / countWrite | L1 1–5；L2 1–10；L3 1–20 |
| compare | L1 5 以内；L2 10 以内；L3 20 以内 |
| add / sub | L1 5 内不进退位 → L3 10 内 → L4 20 内 → L5 100 内口算 |
| addCarry | **必进位**：个位和 ≥ 10 且总和 ≤ 20（L4） |
| subBorrow | **必退位**：被减数个位 < 减数个位，差 ≥ 0（L4） |
| placeValue | L4 两位数；L5 拓展三位 |
| sequence | 等差数列，步长 1–5（L4 起） |
| clock | L3 整点（minute=0）；L4 增加半点（minute=30）；L5 可选拓展刻钟（minute=15/45） |
| money | L3 认面值（CNY）；L4 数钱/付钱不找零；欧元（EUR）为 L4+ 拓展（对齐 §6.8 双币种策略） |
| wordProblem | a、b 取自对应学段加减范围；题干三语模板化 |
| mul | L5：a∈1–9，b∈1–9；支持「口诀限定」模式（如「6 的口诀」b=6 固定、a∈1–9）与全覆盖轮转两种策略 |

- 同一卷内禁止连续出现相同 `(a, b)`；choice 模式干扰项复用 `lib/workspace.ts` 现有干扰策略（数值邻近/符号混淆）。
- **实现拆分建议（吸收补充稿 B）**：实现时可将各 kind 拆为独立纯函数（`generateAddition(level, rng)`、`generateSubtraction(...)` 等，便于逐函数断言硬约束），由统一 dispatcher 按 `kind` + `levels.ts` 学段参数调用；对外契约仍以本节的 `MathQuestion` / `MathGenerator` 为准。
- 固定题 `MathItem`（§9.2）解析后转为 `source: "fixed"` 的 `MathQuestion`（`fixedId` 指向 md 条目 id），与生成器题共用渲染管线（`MathQuestionCard` 按 `kind`/`visual` 渲染）。

## 10. 技术方案

### 10.1 新增依赖（共 2 个运行时依赖，保持轻量）

| 依赖 | 用途 | 体积影响 | 降级策略 |
|------|------|---------|---------|
| `framer-motion` | 页面转场、答题反馈、拖拽排序动画 | ~30KB gzip | `prefers-reduced-motion` 时禁用 |
| `lottie-react` | 吉祥物 Félix、庆祝动画 | ~15KB gzip + 动画 JSON | 加载失败降级静态 emoji |

> 拖拽（分类/排序/拼词/竖式）使用原生 Pointer Events 自研，不引入 dnd 库（幼儿场景需要大吸附容差与简化语义，通用 dnd 库反而增加复杂度）。撒花用 CSS/Canvas 自研（≤1.5s 一次性动画），不引入 confetti 库。

### 10.2 资产目录规范

```

├─ lottie/          felix-idle.json / felix-happy.json / felix-encourage.json / confetti.json
│                   （每个 ≤ 100KB，总量 ≤ 500KB，懒加载）
├─ audio/
│  ├─ sfx/          correct.mp3 / wrong.mp3 / levelup.mp3 / star.mp3 （≤ 30KB each）
│  ├─ songs/        （预留：真人儿歌 mp3，v2.0 可为空）
│  └─ bgm/          （预留：背景音乐 loop，P2）
└─ images/          （预留：内容图片，当前以 emoji 替代）
```

### 10.3 语音方案（沿用 v1 双轨，扩展）

- **TTS**：后端代理 read-aloud-sf（Edge TTS 神经语音 `fr-FR-DeniseNeural` / `en-US-JennyNeural` / `zh-CN-YunxiNeural`）+ 前端 `speechSynthesis` 回退，机制不变；新增：语速参数透传、连播队列（`audioManager.ts` 统一排队，取消语义清晰）。
- **ASR（跟读/跟唱）**：沿用 Web Speech Recognition（Chrome/Edge），`scorePronunciation` 词级打分不变；学段及格线外置到 `levels.ts`。
- **角色对话双音色**：role A/B 映射不同 voice 名（如 fr 用 Denise / Henry），后端与前端回退各自维护映射。

### 10.4 出题引擎设计原则

- 全部生成器为**纯函数**（输入学段参数与随机种子 → 输出题目对象，接口规格见 §9.5），可单测、可重放（同种子同卷），每日挑战以「日期字符串作种子」实现幂等。
- 题目对象统一携带 `subject` / `level` / `kind`，与错题本、统计、周报共用一套渲染管线（`MathQuestionCard` / `LogicBoard` 实现各 kind 的渲染）。
- 数学口算输入组件双模式：数字键盘（L3+）/ 选项（L1–L2），由学段配置驱动。

### 10.5 渲染与构建

- 全部新增页面 SSG（`generateStaticParams` 用于 songs/stories/dialogues）；关卡地图与答题为客户端交互（内容已在构建期注入，无运行时取数）。
- Lottie JSON 与音效在路由级 `next/dynamic` 懒加载。
